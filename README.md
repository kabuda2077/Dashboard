# Dashboard

[简体中文](README.md) | [English](README.en.md)

基于 [zashboard](https://github.com/Zephyruso/zashboard) 的 Windows 桌面代理管理面板，支持 mihomo 和提供 Clash API 的 sing-box。

## 功能

- 管理两套独立核心配置，启动、停止、重启和切换当前核心。TUN 模式开关位于后端主区域；协议栈位于展开的“设置 → 连接设置 → TUN 设置”，在支持时显示，切换可能中断连接。
- 选择代理、测速，查看连接、流量、规则和日志。连接历史是有容量限制的聚合统计，界面在后台运行时也会裁剪并定期保存；低流量统计项可能被移除，再次出现时重新累积。
- 自定义主题、背景和连接标签，导入导出界面偏好。
- 托盘、开机自启、关闭到托盘和轻量模式；轻量模式隐藏一分钟后释放界面，重新打开时恢复。
- 可选来源 IP 主机名解析，默认关闭；手动标签优先，不支持解析时显示原 IP。
- 概览提供八目标 HTTP 请求耗时检查，最多四个目标并发，每站连续采样五次，完成一个目标即开始下一个。数字显示成功样本中位数，采样柱随结果逐根从底部长出，等待和排队的柱子保持静止；失败样本显示红色短柱，减少动态效果设置下停用动画。通过页签切换左侧延迟/分流卡片。分流检测覆盖八个目标，由宿主通过当前核心已有的本地代理入站建立独立 HTTPS 连接，配对后显示最终节点或直连，两者均用绿色圆点表示已确认，未确认时为灰色。底部细线在确认连通后显示绿色，尚未确认或失败时显示灰色，检测时显示流动短线，不表示延迟或百分比进度；没有可用入站时无法检测，不修改配置。进程和入站规则可能与 WebView、TUN 或其他应用不同，结果不代表所有应用；无法配对时显示未确认。
- 延迟与分流可点击单个站点重测，顶部闪电检测当前页全部站点。延迟重测期间保留上次数字，采样柱显示本轮进度，五次完成后更新最终中位数；分流检测期间保留已有结果；同一应用会话内可跨页面及轻量模式释放恢复，完全退出后清空。只在检测卡片可见时自动检查：延迟遵循自动检查开关，超过五分钟后再次查看会刷新；分流首次查看或路径变化后检测，不定时轮询。节点、模式、规则或网络变化会合并触发当前页重测，不显示待更新标签。
- 网络信息并行查询国内和国外出口：国内固定使用 ipip.net，一次取得 IP、位置及运营商，不查询 ASN；国外使用设置中“IP信息API”选定的服务，一次取得该服务实际看到的出口 IP、位置、ISP/组织及 ASN，卡片标题显示当前服务名称。有效地址的归属字段不完整时仍显示地址，缺失字段不作推测。详情按位置、ASN 编号、ISP 排列，国内 ISP 同样右对齐；长文本保持单行，可悬停查看完整位置、ISP 和 ASN 组织。默认遮掩 IP 后半段及国家/地区之后的位置详情；ISP 保留首词、ASN 保留编号，后续各词替换为 `**`，悬停提示也遵循遮挡设置，可手动显示完整信息。地址自然采用服务返回的 IPv4 或 IPv6，不额外探测；查询遵循当前网络及分流规则，不代表所有代理节点。该 API 设置也用于连接详情的在线归属查询；连接列表使用独立的 GeoIP 国家库和 ASN 库。请求耗时不等于 Ping，分流检查不保证网站解锁或完整功能可用。

## 安装与使用

需要 Windows x64、[.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0) 和 [Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)。

1. 从 [Releases](https://github.com/kabuda2077/Dashboard/releases) 下载压缩包，解压后运行 `Dashboard.exe`。
2. 自备 mihomo 或启用 Clash API 的 sing-box，以及对应配置文件。发布包不包含核心和配置。
3. 在 Core 页面选择核心，填写可执行文件、配置文件、API 地址和 Secret，保存后启动。需要管理员权限时会请求 UAC；请使用当前 Windows 账户提权，跨账户提权会取消接力并保留原窗口。

mihomo 使用 `external-controller`，sing-box 使用 `experimental.clash_api.external_controller`。例如 API 地址为 `http://127.0.0.1:9090`，Secret 应与核心配置一致。启动后仍无法连接时，检查 API 地址和 Secret。API 不属于当前受管核心时会提示，并禁用通过该 API 升级 mihomo。

设置位于 Core 页面。连接页面可切换活跃／全部连接；再次点击“全部”可选择仅已关闭。连接统计的聚合方式和表格排序作为界面偏好保存，可随偏好导入导出；不包含统计数据。

## 更新与注意事项

- **从 1.x 升级到 2.x 请解压到新目录并重新配置。** 旧设置、历史、背景图片和启动项不会自动迁移；保留旧目录作为备份。
- 更新 2.x 时，完全退出程序后覆盖应用文件，保留 `settings.json`、核心和配置文件。
- 应用版本变化会清空连接历史、本地背景图片等浏览器数据；已保存的界面偏好会恢复。旧缓存首次切换到当前策略时也会重置一次。
- Secret 受 Windows 当前用户保护。换用户后无法解密时，在 Core 页面重新填写并保存。
- Dashboard 更新会打开下载页，由你手动替换。识别为原版的 mihomo 通过受管核心接口升级，确认自重启后的进程与 API 恢复后才报告完成。TanakaLun、Smart 等已识别的 mihomo 分支和 sing-box 使用“发布页”入口，悬浮可查看说明：下载后停止核心，再替换可执行文件；reF1nd sing-box 指向它的独立发布仓库。未知来源不会回退到原版更新地址，需自行确认下载来源。版本标识只能识别已知格式，无法证明保留原版版本号的自编译核心来自哪个仓库。
- sing-box 通过 Clash API 管理，桌面 TUN 栈只读；不支持 native API、Tools 或 Terminal。TUN 睡眠唤醒后的自动恢复尚未验证。
- 本地界面使用端口 `33291`，被占用时无法启动。自启任务存在归属冲突时不会覆盖，请检查已有任务。

遇到问题可查看 `resources/logs`；需要详细日志时，以 `Dashboard.exe --diagnostic-log` 启动。
