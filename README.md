# Dashboard

[简体中文](README.md) | [English](README.en.md)

**面向 Windows 桌面的 mihomo / sing-box 代理管理面板**，基于 [zashboard](https://github.com/Zephyruso/zashboard) 构建。提供双核心配置管理、节点选择与测速、实时连接与流量统计、规则与日志查看，以及托盘与网络诊断等桌面能力。

- **最新版本**：[Releases](https://github.com/kabuda2077/Dashboard/releases)
- **支持核心**：mihomo、启用 Clash API 的 sing-box
- **运行平台**：Windows x64

---

## 快速开始

### 运行环境

使用前请确保系统已安装：

- **Windows x64**
- **[.NET 10 Desktop Runtime](https://dotnet.microsoft.com/download/dotnet/10.0)**（已安装 .NET 9 的环境仍需安装 .NET 10）
- **[Microsoft Edge WebView2 Runtime](https://developer.microsoft.com/microsoft-edge/webview2/)**

### 安装与配置

1. 从 [Releases](https://github.com/kabuda2077/Dashboard/releases) 下载压缩包，完整解压后运行 `Dashboard.exe`。
2. 自备 `mihomo` 或启用 Clash API 的 `sing-box` 可执行文件及配置文件（发布包不包含代理核心与用户配置）。
3. 进入 **Core** 页面，选择核心类型，填写可执行文件路径、配置文件路径、API 地址和 Secret，保存后启动核心。

> **核心 API 配置对照**
> - **mihomo**：在配置中启用 `external-controller`（如 `127.0.0.1:9090`），Secret 与 `secret` 字段保持一致。
> - **sing-box**：在配置中启用 `experimental.clash_api.external_controller`，Secret 与对应配置保持一致。
> - 启动后仍无法连接时，请检查 API 地址与 Secret。若目标 API 不属于当前受管核心，界面会提示，并禁用通过该 API 升级 mihomo。
> - 需要管理员权限时会请求 UAC；请使用**当前 Windows 账户**完成提权，跨账户提权会取消接力并保留原窗口。

## 功能特性

### 核心与桌面管理

- **双核心配置**：独立保存两套核心配置，支持启动、停止、重启与一键切换当前核心。
- **TUN 控制**：TUN 模式与局域网共享开关位于后端主区域；协议栈选择位于展开的“设置 → 连接设置 → TUN 设置”（在核心支持时显示，切换可能短暂中断连接）。
- **桌面驻留与轻量模式**：支持系统托盘、开机自启与关闭到托盘。托盘图标随 Windows 深浅色模式自动切换颜色，运行中更改模式也会更新。启用轻量模式后，窗口隐藏满一分钟会自动释放界面资源，重新打开时恢复。

### 代理、连接与偏好

- **日常面板管理**：选择代理与策略组、节点测速，查看实时连接、流量、规则和日志。设置集中在 Core 页面。
- **分组图标缓存**：自动缓存代理分组使用的远程图标，支持新增分组和界面自定义图标，再次打开时优先使用本地缓存。
- **连接视图与统计**：连接页面支持切换“活跃 / 全部”连接，再次点击“全部”可筛选“仅已关闭”。连接历史是有容量限制的聚合统计，后台运行时也会定期裁剪并保存；低下载流量项可能被移除，再次出现时重新累积。聚合方式与表格排序会随界面偏好保存和导入导出（不包含统计数据本身）。
- **个性化与来源标识**：支持自定义主题、背景图片与连接标签，导入导出界面偏好。可选开启来源 IP 主机名解析（默认关闭，手动标签优先，不支持解析时保留原 IP）。

### 概览与网络诊断

左侧卡片可通过页签切换 **延迟** 与 **分流**，右侧显示 **国内 / 国外网络出口信息**：

- **延迟检查**：覆盖 8 个目标站点，最多 4 个目标并发、每站连续采样 5 次，数字显示成功样本中位数。采样柱随结果逐根生长，等待项保持静止，失败样本显示红色短柱（遵循系统减少动态效果设置）。
- **分流检测**：覆盖 8 个目标站点，由宿主通过当前核心已有的本地代理入站建立独立 HTTPS 连接，配对后显示最终节点或直连。已确认结果使用绿色圆点与绿色底线，未确认或失败时为灰色；检测中显示流动短线（仅表示正在检测，不代表延迟或百分比进度）。无可用入站时无法检测，且不会修改核心配置。
- **按需与自动刷新**：点击单个站点可重测，顶部闪电按钮检测当前页全部站点。重测期间保留上次结果，同一应用会话内跨页面或轻量模式释放后均可恢复，完全退出后清空。仅在卡片可见时自动检查：延迟遵循自动检查开关且间隔超过 5 分钟返回时刷新；分流在首次查看或路径变化后检测，不定时轮询。节点、模式、规则或网络变化会合并触发当前可见页重测。
- **出口与归属信息**：并行查询国内外出口。国内固定使用 `ipip.net` 一次获取 IP、位置与运营商（不查 ASN）；国外使用设置中“IP 信息 API”所选服务一次获取出口 IP、位置、ASN 与 ISP/组织，卡片标题显示当前服务名。详情按“位置｜ASN 编号｜ISP”排列，支持单行省略与悬停查看完整信息；隐私遮挡开启时，正文与悬停提示均同步遮掩。该 API 设置同时用于连接详情的在线归属查询，连接列表则使用独立的 GeoIP 国家库与 ASN 库。

> **诊断说明**：HTTP 请求耗时不等于 ICMP Ping；宿主分流探测的进程与入站规则可能与 WebView、TUN 或其他应用不同，结果不代表所有应用，也不保证目标网站解锁或完整功能可用。

## 更新与升级说明

### 日常更新（2.x）

- 从系统托盘**完全退出** Dashboard，解压新版本并覆盖应用文件，保留原有的 `settings.json`、核心程序和配置文件。
- 应用版本更新会重置 WebView 浏览数据（连接历史、本地背景图片等会清空，需重新选择本地背景），已保存的设置与界面偏好会自动恢复。

### 从 1.x 升级到 2.x

- **请勿直接覆盖旧目录。** 请备份原目录后，将 2.x 解压到新的空目录并重新配置；1.x 的设置、历史、背景图片和自启项不会自动迁移。

### 应用与核心更新方式

- **Dashboard 本体**：在关于区域检查更新后打开下载页，手动替换文件。
- **原版 mihomo**：识别为原版时通过受管核心接口升级，待自重启后的进程与 API 确认恢复后才报告完成。
- **内核项目主页**：点击顶部内核版本号可打开已识别内核对应的 GitHub 项目主页，例如 TanakaLun 指向 `TanakaLun/mihomo`，reF1nd sing-box 指向 `reF1nd/sing-box`；未知来源不跳转到固定仓库。
- **手动更新内核**：TanakaLun、Smart 等已识别分支及 sing-box 的“升级内核”按钮会打开对应发布页，悬停可查看手动更新提示；原版 mihomo 当前无法直接升级时也可通过此按钮打开发布页。reF1nd sing-box 指向其独立发布仓库。下载后先停止核心再替换可执行文件。未知来源时按钮禁用，不会回退到原版更新地址，请自行确认下载来源。

## 注意事项与故障排查

- **sing-box 支持范围**：通过 Clash API 管理，桌面端 TUN 协议栈为只读；不支持 native API、Tools 或 Terminal。TUN 在系统睡眠唤醒后的自动恢复尚未验证。
- **凭据保护**：Secret 使用 Windows 当前用户凭据加密保存。切换系统用户后若无法解密，请在 Core 页面重新填写并保存。
- **端口与自启**：本地界面使用端口 `33291`，被占用时无法启动。自启计划任务若存在归属冲突不会强行覆盖，请检查系统中已有任务。
- **日志排查**：运行日志位于 `resources/logs`；轻量模式释放界面后，从托盘恢复的阶段计时默认记录在 `performance.log`，同一次恢复使用相同的 `trayRestore id`。`elapsedMs` 从恢复请求起计时，`durationMs` 为阶段或事件耗时，`documentMs` 为前端导航后的时间，`sincePreviousMs` 为相邻前端标记的间隔；`frontendReady` 表示初始路由就绪并经过浏览器绘制机会，不包含核心 API 就绪或物理屏幕呈现。需要其他详细诊断信息时，可使用 `Dashboard.exe --diagnostic-log` 启动。
