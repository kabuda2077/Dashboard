# 维护约定

本文是 Dashboard 长期维护规则的唯一说明入口；[README](../README.md) 保留使用和开发命令，[ownership.json](upstream/ownership.json) 保留工具消费的准确上游基线、路径归属、规则引用、检查入口与持续待办。历史由 Git 追溯，每轮差异、日志和截图放在 `.tmp/reports/`，不默认新增版本文档或第二份登记。记录完整、合并无冲突、构建通过、行为通过分别说明实际含义，均不自动授权推送或发布。

保留已确认的产品行为与体验，允许用经过验证的上游实现替换本地实现；不以组件名、历史像素或本地差异数量作为目标，也不把已接受的差异自动列成重构任务。替换须证明对应规则仍成立，并让旧实现退出活动路径。新产品范围、明显或不确定的体验变化需要具体比较和产品决定，已有决定只在相关条件变化时重议。

<a id="desktop-shell"></a>
## 桌面壳与 Core 工作流

- 桌面采用一个活动核心、两个独立 profile；页面为 Core、Proxies、Connections、Overview、Logs、Rules，设置嵌在 Core 且通常折叠。保留 mihomo 与 sing-box 的 Clash-compatible API 支持。浏览器预览没有本机宿主权限，连接记录独立。
- 进程、窗口、托盘、自启、文件选择、凭证和可执行文件更新由可信宿主管理。核心操作只有一条路径和不排队的操作门禁，保存与依赖操作协调；桌面选项和文件选择不暗中提交核心草稿。
- 正常编辑跟随活动核心；切核时明确编辑目标的独立草稿。运行状态更新不覆盖草稿；取消不改变草稿、运行态、已保存 profile 或背景布局/滚动位置。保留脏状态、冲突及需重启提示，未改变时禁用保存，失败不能显示成功。
- 首次设置保留同时配置两核的完整对话框，含 exe/config/API/Secret、文件选择和专属帮助。启动只提交所选草稿，API 就绪与持久化 `completeSetup` ACK 共同决定关闭；提权/启动失败回到可见恢复入口。Core 原生对话框内的重载/丢弃确认仍在其中，保留取消、焦点和过期上下文保护。延迟加载的设置内容完成后再测列宽或定位深链接，目标变化取消待执行导航。
- 保留状态与 Switch/Start/Stop、重载配置、重启、DNS/Fake IP 清理、支持的 GEO 更新、核心升级及可选 Smart 操作；版本/升级指示采用宿主状态。窗口控制独立，不被滚动隐藏，普通交互控件不能触发拖动/缩放。
- 关闭到托盘、挂起、延迟释放 WebView、退出分别处理；轻量模式隐藏 60 秒后释放，提前打开取消释放。提权会重启整个桌面程序，先完成保存与退出确认，失败或取消保留旧宿主。可信桥与 DPAPI 不构成宿主/WebView 间的强权限隔离。
- 自启任务写入/删除前核对当前用户、exe、工作目录；无法确认归属或属于其他目录/用户时拒绝，不强制覆盖。退出等待已接受的自启变更及结果保存。
- 生产 UI 固定为 `http://127.0.0.1:33291/`，端口占用明确报错。更改来源必须验证 API/WS 兼容与安全策略，不能用关闭浏览器安全解决明文远端 API 限制。

<a id="shared-controls"></a>
## 共享控件与消费者

优先采用上游通用控件、渲染与计算；当前已用 SelectInput 替代重复下拉，SegmentedControl 保留键盘导航，但组件名不是约束。菜单支持选择、外部点击/Escape 关闭和可见键盘焦点；页面手势不得抢占横表、编辑或纵向滚动。Tooltip 保留触摸检测和纯文本安全。更改控件、样式或依赖时检查真实桌面消费者，即使消费者文件没改；登记的 watch 只是最小检查图，不是完整依赖分析。确认尺寸、键盘、焦点与消费者行为等价后，可直接复用上游并删除多余本地适配；退出镜像登记也须有来源与验证依据。

<a id="host-session"></a>
## 宿主、会话与数据生命周期

- 宿主拥有身份、epoch、进程和操作结果；数据请求不能越过会话边界。相同端点的重启/切换也使旧异步结果失效；命令按 request ID 配对，增量 nullable 字段可清除旧值。进程存在、API 就绪与保存 ACK 不能混为一谈。
- 会话就绪后统一初始化配置、规则、代理及连接/统计/日志流，切页不重复订阅；所有页面（包括概览）离开销毁、返回重建，跨页面任务与数据不依赖组件存活。不要恢复整页 KeepAlive。
- 未知 TUN/API 状态不当作关闭。加载、失败、未知、禁用、只读可区分，只读 TUN 说明来源；清空数据后仍保留当前会话鉴权/连接错误。会话未就绪时 Retry 重探宿主，普通配置读取失败重试 API，写失败恢复已确认开关值。
- sing-box 使用 Clash-compatible API，不转 native API/protobuf；版本优先 `/version`，保留宿主可执行文件版本回退。核心/config 升级由宿主管理，运行中 sing-box 升级必须确认新 API 就绪，失败恢复原文件并尝试重启原核。无摘要升级确认 `ConfirmUnverified` 必带 `expectedRevision`、`expectedRuntimeEpoch`；普通升级可省略，但携带时必须匹配。

<a id="preferences"></a>
## 配置、凭证与持久化

- 使用 `schemaVersion=2`、桥接 v2 和独立 `resources/webview-data-v2/`；宿主与前端整包更新。磁盘键 `singBox` 与桥接键 `sing-box` 不混用。无文件创建完整默认文档，已有格式不符明确报错并保留原件，不静默补字段/覆盖；字段校验以 [AppSettings.cs](../src/AppSettings.cs)、[SettingsStore.cs](../src/SettingsStore.cs) 为准。
- 不迁移/删除 1.x 设置、profile、凭证、浏览器数据或启动项。Secret 用当前用户 DPAPI，无法解密时在使用前要求显式替换（包括空值），普通保存保留原密文。
- 导入会初始化偏好的应用模块前先恢复 bootstrap 偏好；保留原子提交、请求/ACK 与独立草稿。挂起/释放前等待偏好、历史及图片完整读取/解码/提交，退出保存未确认须反馈，发送消息不等于落盘。
- 同版本重启、窗口重建或前端资源替换保留浏览器数据。应用版本变化或版本标记无效时，创建 WebView 前只删除 v2 的 `EBWebView`；成功后原子保存独立 `.webview-content-version` 的纯版本号，不扫描资源指纹。失败不启动、不标记完成；旧缓存策略切换重置一次，不迁回旧数据。
- 重建会清空浏览器连接历史/本地背景，但保留宿主 settings、核心、配置、icon-cache、日志及 1.x `resources/EBWebView`；已提交偏好仍按 v2 启动协议恢复。

<a id="notifications"></a>
## 通知与信任边界

API/宿主/外部错误和 tooltip 字符串按文本渲染，富内容走独立清洗路径。保留当前会话的失败反馈，旧会话错误不干扰当前操作；取消、失败与成功明确区分，复制/保存提示只在操作真正成功后给出。

<a id="proxy-experience"></a>
## 代理体验

保留有效代理文件夹、分组/筛选、标签、测速与测速排序、滚动恢复及宿主图标缓存。上游虚拟化、延迟计算与渲染可替换本地实现，前提是选择和导航语义可用；不把缓存名或组件名变成永久规则。移动代理遮罩的待决定项见登记 `pending`，桌面 WebView 结果不能代替移动浏览器比较。

<a id="tables-history"></a>
## 表格、日志与连接历史

- 保留 Clash 字段、链路、分组、数字排序、复制、GeoIP 延迟加载与历史持久化；复用 VirtualTable，移除重复实现。未支持 native API 的空分支不是功能。
- 连接“搜索隐藏列”默认关闭，仅搜展示字段；隐藏连接正则检查全部支持字段。保留已知字段直接迭代的搜索访问器，不能引入按数组引用缓存导致原地改列后过期。表头与工具栏浮层层叠正确，支持独立表头宽度/表格样式，避免重复原生 title。
- 规则命中/未命中两列分别数字排序，命中时间可见；缺时间不伪造当前时间，tooltip 为静态 DOM 文本。请求失败/忙碌保持已确认开关；命中数是请求快照，不定时轮询。
- API 日志按保留上限收集；暂停/隐藏只冻结发布，恢复立即显示最新保留记录，清空包括待显示记录。WebView 挂起/销毁不保证采集，不能当作宿主进程日志或后台持久服务。
- 连接历史保留提前采用的后续上游公共后缀修复 `tldts`；不为迁就旧基线退回错误的域名归类。

<a id="overview-charts"></a>
## 概览任务与图表

概览遵守页面重建。共享统计、IP 查询和连通性任务跨导航继续完成，返回显示当前结果与忙碌状态，不重复查询；网络测试四个目标、每个十次采样。隐藏/脱离文档不绘图，暂停不因仍挂载就重绘；局部图表暂停状态可随重建复位。替换图表/任务实现须验证共享归属、有界数据和可见性边界。

## 当前排除与暂缓范围

## 工具、来源与上游跟进

### 当前仍有效的取舍

准确比较基线与镜像以 [ownership.json](upstream/ownership.json) 为准：推进基线表示已逐项审查，不表示上游全量原样采用或运行验收通过。v3.26 已采用的 API 生命周期、通知/持久化、虚拟化/排序、连接链路/GeoIP、主题/CSS/可访问性改进继续保留；v3.27 的隐藏列搜索、表格层叠/宽度、规则 tooltip 等采用与适配已归入上面的行为约定。Core 仍内嵌设置，不为独立 Settings 加回路由映射；上游 CHANGELOG/图标生成不替换 Dashboard 发布说明/PowerShell 图标链，前端上游版本与 Dashboard 产品版本分别管理。

在 v3.27.0 比较基线上已部分采用后续提交 `686234ab252e3517a2ca5113477eedc8376203d7`：来源 IP 标签匹配忽略 IPv6 zone，保留本地文件名、正则原始地址、未匹配值及会话缓存语义。同一提交的反向 DNS 部分未采用。v3.29.1 的数据层/命名迁移、视觉与移动导航、dae 和其余独立修复仍需后续处理；本轮不推进比较基线，剩余变化仍从原基线可见，不能把本候选称为完整 v3.29.1。

持续问题以登记 `pending`/`knownGaps` 为唯一清单；品牌图标（`upstream-327-brand-icon`）和移动代理遮罩/状态栏（`upstream-327-mobile-overlay`）仍待决定，具体保留行为与重审条件查登记，不因完成审查或桌面测试自动解决。`VirtualColumn` 实例内尺寸缓存只是尚无收益证据的可选清理，不自动形成改造任务。旧 TUN 睡眠唤醒自动重启已撤下，替代方案尚需单独实现与验证。

### 一轮跟进

公开入口为 [tools/review-upstream.ps1](../tools/review-upstream.ps1)，各阶段使用同一入口。固定 **U0**（登记的旧上游 revision）、**U1**（其后继目标提交）、**D**（实施起点 HEAD 与 dirty/untracked 源码）；上游根映射 `dashboard-src/`。保护既有工作，在分支/隔离检出中集成，不静默 stash/reset。`v1.3.2` 只作可选来源，不是必备比较输入。

1. **计划**：工具给出真实本地差异、上游文件/提交/重命名线索、消费者和去重检查建议；审查者按行为确认功能组及文件覆盖。一个功能可跨文件，一个文件可属多组；多组都暂缓或都保持原文件时合并核对，实际修改或处理方式不一致时声明范围/例外。普通修复可经过内容判断后批量处理，未知范围与归属碰撞不能自动批准。
2. **实施**：保留不可变计划证据，以一份可编辑记录维护理由与结果。区分采用、适配、上游替换本地、保留和暂缓；替换要指出新实现、旧实现删除/退出调用链、保留适配和验证。既有理由可以复用，候选改变后相关实现与测试须复核，不能手改指纹让旧验证变新。
3. **结果**：结果引用计划并绑定实际候选，写明偏离与真正执行的验证。起点按 U0 检查，结果依据明确采用范围识别 U1 新增文件与镜像；不要把上游新增登记为永久本地所有，也不放松全部镜像校验。记录完整不证明理由真实、文件内语义全覆盖或检查已执行。
4. **结案/基线**：核对实际采用与验证，保留/排除引用既定规则，暂缓/未实施带原因、重审条件与依赖进入持续待办，再推进准确比较基线及镜像来源。旧实现与失效登记同时退出；镜像哈希来自选定上游 blob，不能来自自行认可的本地编辑。下一轮继续看得到遗留项。

同一入口通过 `-Phase Plan|Review|Result|Close` 选择阶段（默认 Plan），共同指定 `-UpstreamRoot` 与本轮 `-OutputDirectory`，Plan 另指定 `-TargetRef`。准备上游干净检出于 U0，并提前 fetch 目标提交；工具本身不获取或合并源码。Plan 生成不可变起点与可编辑的 `decisions.json`；按功能填写后运行 Review 固定实施决定。实施完成后首次 Result 捕获候选输入，填写同一记录中的实际结果与验证，再运行 Result 核对。候选再次变化时用 `-Phase Result -ResetResults` 清除旧结果后重新验证；处理决定本身变化则需要新的计划。Result 的 `results.json` 同时给出 `policyProposal`，供核对后更新基线、持续待办、镜像及保留旧文件的来源映射；它不自动改登记。Close 只在完成这些承接、更新登记及上游检出到目标提交后核对基线推进。

局部采用可以保留原比较基线，不强行将尚未完成的目标声明为已跟进版本；下次仍从原基线审查剩余变化。只有推进基线时才需要 Close，测试夹具中的结案不代替实际产品集成结果。准确参数与记录格式以同一公开脚本为准，不建立阶段专用入口。`forkOwnedPaths` 只声明 U0 不存在的精确本地文件或专属命名空间；已有上游文件即使重写/删除仍是共享文件，U1 撞入本地路径必须审查。风险按数据/权限/会话/交互后果判断，不按行数。使用 Git 差异/重命名/三方合并与既有验证，不能靠 ours/theirs、迁移文件或重写架构掩盖行为冲突。

<a id="verification"></a>
## 验证与产物

- 日常先运行相关测试；文档/工具运行 `pwsh -NoProfile -File .\tools\check.ps1 -Scope Maintenance`。默认 `-Scope Application` 不重复维护检查，需要两者时用 `-Scope All`。正式候选直接走既有 `create-release.ps1 -IncludeWebViewIntegration -IncludeRealCoreIntegration`（先准备隔离核心），不要先重复完整 Check；命令及前提见 [README](../README.md#开发与验证)。
- 保留实际 WebView 布局、鼠标命中、桥接保存和生命周期验证。闲置释放先核对生产 60 秒，再加速真实计时器；API 永不就绪场景只缩短测试实例预算。排序/筛选组合由前端回归覆盖，不在每个语言/尺寸重复整套。类型检查复用增量构建，包完整性/发布输入仍每次核对。
- 视觉比较使用相同 fixture、字体、主题、语言、viewport，记录源码/dirty 输入；用相对几何，不把动态日志/时间当截图判据。CoreLayoutTests/CoreSetupLayoutTests 检查真实 DOM、隔离宿主/profile/API，SyntheticClashApi 不访问默认 9090；用本次运行产物确认 CI 实际执行。初始切核滚动、工具栏尺寸、未知配置状态问题已修复，不继续列作待办。
- 默认保存代表截图与失败诊断；视觉改动可设 `DASHBOARD_UI_VISUAL_COMPARISON=1` 跑同一 WebView 验证，结束清除。覆盖 Core/settings、代理、连接/日志/规则、概览，以及侧栏两态、明暗、中英、窄宽；错误/忙碌/焦点/背景/缩放按影响选择。截图不能代替行为与几何，不能因实现变化就刷新截图或删断言；等效调整同步理由、比较证据、参考与检查。自动后台执行不新开控制台，保留日志。
- 性能与真实在线升级按影响选择。`OnlineUpgradeIntegration` 不在常规 Check/Release 内，须单独选并准备隔离核心；`alreadyLatest` 不证明实际替换新版。性能比较同环境/负载，并确认窗口真正恢复可用；测试宿主、离屏和短时压力不能代替应用内存、物理帧率或长期泄漏。
- `.tmp/tests/` 使用独立运行/用例标识，测试核心夹具在其 `fixtures/`；`.tmp/experiments/` 放调查/验证副本，`.tmp/reports/` 放日志/截图/wire/性能证据。共享辅助类先释放自建浏览器/进程，再有限重试清理，失败报告路径。生产 TEMP、同盘核心暂存/备份不受此规则影响。pnpm 遵循用户 store/cache，用 `.node-version` 与前端 `packageManager` 固定工具版本，runtime 复用 pnpm 共享缓存，不建 `.tmp/toolchain`。
- `artifacts/releases/` 仅 ZIP，`artifacts/verification/<包名>/` 保存输入清单/摘要，历史候选放 `artifacts/archive/`。不将产物复制到 docs；项目只编译 `src/**/*.cs`，临时/归档/依赖目录在项目项中排除，不能只靠 .gitignore。
- Release 验证前固定 HEAD、tracked/untracked 源清单，验证后及发布/替换 ZIP 前再比对，改变即停止并保留旧 ZIP；侧车记录起始输入。派生的 app/tray.ico 不参与源快照，包文件仍逐项验哈希。Version、InformationalVersion、正式 tag 一致。
- 测试存在不代表本次执行，通过只覆盖实际输入/环境/断言。前端 wire fixture 使用本次宿主测试生成的数据，不用旧产物证明协议。共享控件或会话变化还需验证消费者，不另建上游专属测试流水线。

<a id="system-boundaries"></a>
## 系统验证边界

当前现场覆盖缺口查登记 `knownGaps`（`system-acceptance-boundary`）；以下是长期按改动选择的检查边界，不把全部场景写成当前缺陷，也不要求每次维护全部重跑。自动化的注入 OS 边界、真实 WebView/隔离核心测试不能代替现场结果。

| 涉及改动 | 现场需要核对 |
| --- | --- |
| 启动/提权/自启/凭证 | 真实 UAC 同意/取消、登录任务生命周期、跨账户 DPAPI、缺 Runtime/损坏包、生产单实例与提权接力。 |
| 窗口/布局/输入 | 不同 DPI、跨物理显示器、触摸和原生焦点；离屏布局不代替设备验收。 |
| 持久化/发布/资源 | 完全退出生产 EXE、覆盖更新再启动；宿主数据保留、浏览器按版本重建、同版本资源替换保留、不触碰 1.x。仅宿主/UI 资源替换测试不等于完整 EXE 更新。 |
| 升级/网络/剪贴板 | 真实新版下载与失败恢复、目标网络和系统剪贴板成功路径。 |
| 睡眠/网络恢复 | 专用 TUN/物理网络的睡眠唤醒，及其间切核/重启。 |

系统任务、UAC、TUN、电源与用户数据验证使用专用账户/VM、隔离核心/数据，并取得相应授权，不接管用户现有实例。按候选实际结果说明覆盖；通过自动检查或生成 ZIP 不等于系统验收完成。

只把需要长期遵守、代码/测试不能清楚表达的约定写入本文；问题优先形成可复现步骤与正式回归，不追加实施流水账、阶段审计或验收总表。
