# 上游跟进

仅供比较、采用和登记上游变化时使用。基础工作规则见 [AGENTS.md](../AGENTS.md)，架构边界和检查入口按需查阅 [development.md](development.md)；普通开发无需阅读本文。

基线、来源、路径、检查入口和待办以 [ownership.json](upstream/ownership.json) 为准，不在本文重复版本流水。登记中的 `rule` 指向对应边界或决定，`watch` 只是影响线索，不是完整依赖图。具体功能以代码、测试和用户说明为准，不为每次采用的功能追加保留清单。

<a id="excluded-product-scope"></a>
## 采用边界与本地差异

- 独立 Settings、多后端桌面管理、dae、sing-box native API/protobuf、Tools、Terminal、Tailscale、USB/IP、OpenVPN、DNS Query 页面、Earth/HonkStats 和上游 UI 自升级不在当前范围；改变范围需新的产品决定。排除模块中的通用修复可单独采用。
- iOS 状态栏/Safari 专用适配、Android/KernelSU 入口、手机浏览器安装和系统手势联动等移动平台专属逻辑不引入，也不维护移动平台验收。混合改动拆出桌面适用部分；无桌面影响的简单兼容样式可随共享实现保留，不构成移动支持承诺。桌面适应性按 development 的布局约定判断，不因 `Mobile` 命名或来源排除通用改进。
- 上游发布说明、部署样例、文档和图标工具不替换本地发布、品牌及图标链，也不随桌面分发；测试脚本仅按本地验证需要选择。旧 TUN 睡眠唤醒自动重启已撤下，替代方案需另行验证。
- 采用上游组件时检查宿主权限、会话、持久化及既定视觉选择是否受影响，相关边界见 development 对应章节；确认行为和外观等价后移除重复适配。无需重审无关模块或复制完整功能规格。

<a id="upstream-following"></a>
## 工作顺序

收到上游跟进请求时使用本文。**默认只跟进最新正式 Release**（排除 draft/prerelease），核对发布、tag 和准确 SHA；未发布 main 不进入范围，除非用户明确指定。固定上游基线 U0、目标 U1 和本地起点（HEAD、dirty/untracked 源码），新发版留待下一轮。先核对祖先关系，已有提前采用的提交不自动回退；目标已被基线包含时保留现有基线，补齐内容按准确来源登记。

| 步骤 | 要求 |
| --- | --- |
| 分析 | 只读比较上游与本地，按功能分组，复用已有决定。向用户展示下面三类清单，不能只写在本地报告。 |
| 确认 | 留出审阅机会，必要取舍明确后实施；普通修复不逐项再问。用户明确允许直接项先做时，可推进独立部分。 |
| 实施 | 按确认范围推进，普通技术适配自行处理；说明实际改动、偏离和阻塞。 |
| 复核 | 按通用复核规则，对照确认清单检查实现和保留约束。 |
| 报告 | 对应原清单说明实际采用、决定落实、偏离、验证及限制、待办变化和交付状态。普通项简述，重要取舍展开。 |

实施前清单：

- **直接跟进**：简述问题、本地变化及验证。
- **需要确定**：说明当前/上游行为、影响、收益与代价、建议和选项；视觉变化按需提供同条件比较。新增操作、限制既有操作、持久化/权限或不确定体验变化都在此列。
- **等价实现／既定决定**：给出等价依据或规则引用，条件未变不重复询问。

**未回答不等于同意，未决不能自行改成暂缓。** 暂缓要有明确决定、原因和重审条件；已有排除/暂缓直接复用。对话决定是确认依据，工具状态不是批准证书。

## 范围与待办

功能可跨文件，文件可含多项功能；处理冲突才需说明范围例外。补路径、使用页面或归属不重建计划。替换说明新实现、旧实现退出方式和保留适配。

按[采用边界](#excluded-product-scope)筛选上游变化。桌面适应性、通用输入交互及其外观改进按既定决定列入清单，不因移动风格重复询问；涉及其他产品边界、持久化或权限的新取舍仍先讨论。验证范围按 AGENTS 选择，项目入口见 development。

旧待办自动承接，仅在本轮触及、依赖/决定改变、达到重审条件或用户要求时展开；文件交集只是线索。只审触及范围，不重审整个大组，不因同文件的小修消掉另一项未实施功能。未触发项只统计。

待办承接和来源校验由现有工具测试覆盖，日常不再模拟下一轮。

## 工具操作

使用 [review-upstream.ps1](../tools/review-upstream.ps1) 和一份可编辑 `decisions.json`：

| 操作 | 内容 |
| --- | --- |
| `-Phase Plan`（默认） | 指定干净 U0 检出 `-UpstreamRoot`、固定 `-TargetRef` 和 `-OutputDirectory`；保存起点清单并检查目标归属。人工重审用 `-Revisit <id>`。 |
| `-Phase Review`（可选） | 刷新当前清单和修订摘要，不是批准门禁，可在实施中使用。 |
| `-Phase Prepare` | 实施与必要复核收齐后，核对实际 diff/来源，更新候选登记并保存快照；指定 `-AdvanceBaseline` 才推进基线。随后按[验证与产物](development.md#verification)运行一次既有最终检查或 Release。 |
| `-Phase Complete` | 在记录中集中填写 `review` 和 `evidence` 后，一次输出绑定候选的完成结果，不修改源码。 |

各次使用同一输出目录，起点和目标不变；工具不 fetch/切 checkout，后续可省上游路径。当前格式为 schema 4，旧报告留作历史，新轮用新目录。

批次记录 ID、路径、处理方式与理由，`localPaths` 无额外使用页面/路径时可省略。未决用 `pending`，可补影响/选项/建议；暂缓用 `defer` 并写重审条件；修订决定填 `revisionReason`。原样采用、适配、替换、保留和暂缓分别记录；局部采用可保留 U0，推进基线须承接未解决项。

源码或决定变化后重新 Prepare，旧验证记录失效；输入不变则保留。Complete 输出的完成记录不可变。

本地所有声明仅用于上游不存在的精确路径/专属空间，共享文件即使重写或删除也不改归属；目标新文件碰撞须审查。实际修改有明确范围，保留旧文件有有效来源，镜像哈希来自上游 blob。不得以强制选边、改指纹或迁移文件掩盖冲突。
